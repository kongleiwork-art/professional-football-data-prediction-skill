# 模型规则

目标：先建立可复现的概率底座，再生成战术解释。不要先写故事再倒推概率。

## 1. 预测不能跳过数据层

每个预测必须先说明：

- 预测生成时间
- 数据截止时间
- 数据来源名称和来源日期
- 样本窗口，例如近 5 场、近 10 场、赛季至今、国家队近 12 个月
- 哪些是确认事实，哪些是模型假设

至少引用 4 类数据依据：

- 赛程与比赛背景
- 近期战绩与进失球
- xG / xGA / 射门质量
- Elo / FIFA 排名 / 联赛强度
- 伤停 / 停赛 / 预计首发
- 阵型与战术风格
- 关键球员状态
- 休息天数 / 旅行 / 天气
- 红黄牌风险 / 裁判尺度 / 球场质量 / 海拔
- 积分或晋级压力
- 市场赔率和隐含概率

## 2. 推荐数据源与开源参考

可参考这些开源项目和公开数据思路：

- `soccerdata`：从 Club Elo、FBref、Football-Data.co.uk、Sofascore、Understat、WhoScored 等来源抓取并统一成表格。
- `penaltyblog`：足球 Poisson、Bivariate Poisson、Dixon-Coles、Bayesian、Elo/Massey/Colley 模型。
- `worldfootballR`：从 FBref、Understat、Transfermarkt、Fotmob 等来源抽取球队和球员数据。
- `football-data.co.uk`：历史赛果、技术统计、赔率 CSV，用于回测和市场校准。

如果没有实际运行这些工具，只能写“方法参考”，不能写“已使用该包计算”。

## 3. 期望进球估计

预测必须先估计两队 `lambda`：

### xG 缺失补救梯子

不要在缺少逐场 xG/xGA 时只写“保守估计”。必须按以下顺序补救，并标注使用了哪一层：

| 层级 | 名称 | 可用数据 | 置信度 |
|---|---|---|---|
| A | direct_xG | FBref、Understat、FotMob、Sofascore、WhoScored、Opta/官方技术报告的 xG/xGA | 高/中 |
| B | proxy_xG | 射门、射正、重大机会、禁区射门、定位球射门、被射门 | 中 |
| C | goals_regressed_xG | 近 5-10 场进球/失球 + 赛事均值 + 对手强度回归 | 中低 |
| D | strength_prior_only | Elo/排名、阵容、赔率、主客场、战术匹配 | 低 |

如果使用 B/C/D，报告必须写出：

- 为什么 direct xG 缺失。
- 用了哪些替代指标。
- proxy 或回归的计算口径。
- 这会如何放宽概率区间。

射门数据存在时，推荐 proxy xG：

```text
proxy_xG_for = 0.06 * shots
             + 0.05 * shots_on_target
             + 0.18 * big_chances
             + 0.03 * box_shots
```

以上都使用每场均值。被动端同理计算 `proxy_xGA`。如果对手强度明显偏弱，将 proxy 下调 5%-15%；如果样本来自高强度对手，可小幅上调，但必须说明原因。

| 因素 | 默认权重 | 说明 |
|---|---:|---|
| 近期 xG/xGA | 40% | 近 5-10 场非点球 xG、xGA、射门质量 |
| 赛季/赛事基线 | 25% | 赛季至今或赛事至今的攻防水平 |
| 对手防守/进攻调整 | 15% | 对手 xGA、被射门、禁区保护、门将 |
| Elo/排名强度先验 | 10% | ClubElo、FIFA 排名、联赛强度差 |
| 阵容与比赛环境 | 10% | 伤停、主客/中立、休息、旅行、天气、战术匹配 |

国家队样本少时，可以提高 Elo/排名和球员身价/俱乐部分钟数等先验权重，但必须降低置信度。

`lambda` 一般限制在 0.20 到 3.50。超过范围必须解释。

## 4. 阵容可用性折算

不能只写“某球员缺阵所以有影响”。必须把能上场人数和关键缺阵折算成小的进球调整：

| 字段 | 含义 | 默认影响 |
|---|---|---:|
| availablePlayers | 可上场/入选名单人数 | 低于 baseline 每少 1 人约 -0.012 球 |
| unavailableStarters | 缺阵预计主力 | 每人约 -0.055 球 |
| doubtfulStarters | 存疑预计主力 | 每人约 -0.028 球 |
| unavailableAttackers | 缺阵攻击手 | 主要降低本队 lambda |
| unavailableMidfielders | 缺阵中场 | 同时影响攻防和控制 |
| unavailableDefenders | 缺阵后卫 | 主要抬高对手 lambda |
| unavailableKeyPlayerGoalImpact | 明星/门将缺阵手动影响 | 0.00-0.30 球 |
| keyPlayerAttackImpact | 关键攻击手/创造者可用或缺阵 | 有符号进球调整 |
| keyPlayerDefenseImpact | 关键防守者/后腰可用或缺阵 | 有符号防守调整 |
| goalkeeperImpactAdjustment | 门将可用性/状态 | 有符号防守调整 |
| lineupContinuity | 首发连续性 0-1 | 越低越降低战术稳定 |
| regularStarterShare | 预计首发中常规主力比例 | 越高越稳定 |
| clubMinutesShareLastYear | 过去一年俱乐部出场分钟可靠性 | 越高越稳定 |
| clubPerformanceAttackImpact | 俱乐部进攻表现/角色影响 | 有符号进攻调整 |
| clubPerformanceDefenseImpact | 俱乐部防守表现/角色影响 | 有符号防守调整 |
| daysSinceLastMatch / matchesLast14Days / matchesLast30Days | 连续比赛强度 | 影响体能和下半场稳定 |

自动折算只作为先验，必须被具体球员质量和位置修正。门将、中卫核心、单核前锋的缺阵权重高于替补边路球员。

最近一年俱乐部表现要优先看“是否经常主力”和“在什么级别主力”：

- 五大联赛/欧冠稳定主力的权重高于低级别联赛短期高光。
- 国家队替补但俱乐部连续主力，可以提高 lineupContinuity 或 clubMinutesShareLastYear。
- 俱乐部长期替补/伤后复出，即使名气大，也要降低 sharpness。
- 高强度连续比赛会降低下半场 pressingIntensity、staminaProfile 和防守回追。

## 5. 每场特殊因素

每场比赛必须单独建一层特殊因素，不要只放进“不确定性”：

| 因素 | 字段 | 主要影响 |
|---|---|---|
| 裁判尺度 | refereeCardsPerMatch | 红牌、点球、定位球、比赛中断和波动性 |
| 球队纪律 | homeRedCardRisk / awayRedCardRisk | 少打一人情景、尾部比分、爆冷概率 |
| 球场质量 | pitchQuality | 传控质量、射门质量、失误率 |
| 天气 | weatherSeverity | 节奏、体能、门将处理球、传中和定位球 |
| 海拔 | altitudeMeters | 客队体能衰减、下半场回防速度 |
| 主场氛围 | homeCrowdAdvantage | 压迫强度、判罚压力、主队 momentum |
| 主场球迷强度 | homeCrowdIntensity | 前 20 分钟压迫、情绪波动、判罚压力 |
| 客队旅行疲劳 | awayTravelFatigue | 客队体能、回防、下半场失误 |
| 比赛动机 | matchMotivation | 轮换、保守程度、落后后风险偏好 |

默认调整原则：

- 差球场/大雨/大风：降低双方技术型 chance creation，增加失误和定位球波动。
- 炎热/潮湿：降低下半场 pressingIntensity 和 transition recovery。
- 高牌裁判 + 高犯规球队：提高红牌/点球/定位球尾部风险，增加 volatility。
- 高海拔且客队适应不足：降低客队 staminaProfile 和下半场防守稳定性。
- 友谊赛/大轮换：降低模型置信度，提高换人导致的事件流噪声。
- 淘汰赛/必须赢：提高 game-state sensitivity，比分落后方更可能抬高阵线。

脚本会输出：

```text
homeSpecialFactorGoalAdjustment
awaySpecialFactorGoalAdjustment
specialFactorTempoMultiplier
specialFactorVolatilityDelta
specialFactorNotes
```

这些是概率底座的一部分，不是赛后故事。

## 6. 概率模型

## 6.5 临场指挥、定位球、点球

这些因素必须单独建模，不要只写在战术描述里：

| 字段 | 含义 | 影响 |
|---|---|---|
| inGameCoachingImpact | 教练临场调整、半场修正、变阵能力 | 下半场 lambda 和脚本变化 |
| benchImpact | 替补深度、替补角色适配 | 60 分钟后进攻/防守强度 |
| pressingAdaptability | 压迫高度和触发点调整能力 | 前场抢断、二次进攻 |
| buildupPressureWeakness | 对手后场出球抗压弱点 | 被抢断和失误概率 |
| setPieceAttackImpact | 角球/任意球套路、制空点、掩护跑位 | 定位球 xG |
| setPieceDefenseWeakness | 盯人/区域、门将控制、二点保护弱点 | 对手定位球 xG |
| penaltyTakerReliability | 点球手稳定性 | 点球转化 |
| penaltyFrequency / penaltyPressure / varVolatility | 点球/VAR 环境 | 尾部风险和波动 |

建模原则：

- 临场指挥强弱主要影响下半场，而不是开场基础强度。
- 替补深度强的球队在 60 分钟后更容易维持 pressingIntensity 和 transitionSpeed。
- 定位球强队即使 open-play xG 不高，也可能提高 1-0、2-0、1-1 这类低比分路径。
- 点球因素只能提高 volatility 和尾部概率，不能把点球写成确定进球。
- VAR/手球/高牌裁判同时存在时，点球尾部风险上升。

基础模型：

1. 用两队 `lambda` 生成 0-8 球 Poisson 比分矩阵。
2. 累加矩阵得到主胜、平局、客胜。
3. 取概率最高的 3-7 个比分。
4. 若有校准参数，可对 0-0、1-0、0-1、1-1 做 Dixon-Coles 低比分相关修正。
5. 若有 20,000 次以上蒙特卡洛模拟，也可输出模拟结果，但要说明随机种子或等价矩阵算法。

仓库内可执行辅助脚本：

```bash
python3 scripts/football_prediction_sim.py templates/match_input_template.json
```

脚本适合在已有 xG、Elo、主客场和市场概率输入时生成可复现的概率底座。脚本输出是概率参考，不替代数据核验和战术解释。

## 7. 模型校准

优先使用历史预测和赛果做校准，而不是凭感觉调概率。可参考开源足球预测项目常见做法：

- walk-forward out-of-sample：只用预测日之前的比赛拟合校准参数。
- holdout validation：留出某一赛事、赛季或时间段评估。
- Brier score：评估 1X2 概率整体误差。
- log loss：惩罚过度自信的错误预测。
- ECE：检查“70% 概率的事件是否大约 70% 发生”。
- temperature scaling：`T > 1` 软化过度自信，`T < 1` 锐化保守概率。
- public consensus calibration：参考历届世界杯/大众预测/市场预测常见偏差，对重热门、平局和爆冷尾部做保守校准。

仓库内可执行辅助脚本：

```bash
python3 scripts/calibrate_probabilities.py predictions.csv
python3 scripts/backtest_predictions.py data/historical_predictions_template.csv
```

CSV 需要：

```text
homeWin,draw,awayWin,result
0.52,0.27,0.21,H
```

校准参数只能来自历史样本，不能用当前比赛的赔率或主观判断倒推。

大众预测/历史世界杯偏差先验：

- 重热门通常要小幅收缩，尤其是小组赛和友谊赛。
- 平局和低比分尾部通常容易被低估。
- 淘汰赛常规时间强队胜率要考虑加时/点球和保守开局。
- 市场和大众都很热的一方，不代表真实概率可以无限抬高；需要设置 `maxFavoriteProbability` 或 favorite shrink。
- 一旦有自己的 backtest 样本，优先用本仓库历史样本校准，不再依赖默认先验。

赛后复盘流程：

1. 赛前把每场预测追加到 `data/historical_predictions_template.csv`。
2. 赛后补 `actualHomeGoals`、`actualAwayGoals`、`result`。
3. 跑 backtest 脚本看准确率、Brier、log loss、总进球误差。
4. 样本足够后再跑 calibrate 脚本更新 `probabilityTemperature`。

## 8. 市场概率校准

如果有可靠赔率：

1. 将欧赔转换为隐含概率：`1 / odds`。
2. 去除水位：各项隐含概率除以总和。
3. 与模型概率比较。
4. 若单项差异超过 8 个百分点，必须解释原因，例如阵容新闻、模型样本滞后、赔率流动性不足。
5. 只有在市场流动性高且赔率足够新时，才允许少量融合市场概率。

不要把赔率当作唯一依据。赔率是校准器，不是结论本身。

## 9. 参数化方式

将证据转换成 0 到 100 的球队参数：

| 参数 | 含义 |
|---|---|
| attackStrength | 进攻强度，结合进球、xG、射门质量、关键球员状态 |
| defensiveStability | 防守稳定性，结合失球、xGA、被射门、阵型保护 |
| transitionSpeed | 转换速度，反击推进、边路速度、纵向传球能力 |
| pressingIntensity | 压迫强度，前场逼抢、反压迫、压迫触发点 |
| possessionControl | 控球控制力，中场传控、节奏管理、出球稳定性 |
| setPieceThreat | 定位球威胁，角球、任意球、二点球、制空点 |
| goalkeeperImpact | 门将影响，扑救质量、出击、近角封堵、传球 |
| staminaProfile | 体能曲线，休息天数、赛程密度、下半场衰减 |
| tacticalCoherence | 战术一致性，阵型熟练度、球员角色匹配 |
| volatility | 比赛波动性，失误率、红黄牌风险、开放程度 |

参数不能凭感觉打分。每个关键参数至少绑定一个数据依据或明确假设。

## 10. 概率输出

- 主胜、平局、客胜必须合计 100%。
- 比分分布给 3 到 7 个结果。
- 必须展示两队期望进球。
- 概率解释必须说明主要驱动变量。
- 强弱差距不明显时，不应输出极端概率。

## 11. 事件流一致性

- 高威胁回合必须与球队参数和战术风格匹配。
- 比分分布必须能被事件流解释。
- 预测进球数和进球链路数量必须一致。
- 未转化机会应多于进球机会，避免每次高威胁都进球。
- 比赛脚本要随比分变化：领先方可能降低压迫，落后方可能抬高防线。
- 特殊因素要进入事件流：高牌风险写压迫/犯规/定位球，差球场写停球失误，炎热写下半场体能衰减。

## 12. 校验清单

输出前检查：

- 概率是否合计 100。
- `lambda` 是否支撑最可能比分。
- 模型概率和市场概率是否存在大偏差。
- 是否说明了阵容可用性如何折算进 lambda。
- 是否说明了红黄牌、球场、天气、海拔、动机等特殊因素。
- 是否报告了校准指标，或明确校准样本缺失。
- 缺失数据是否进入不确定性。
- 是否误把传闻、旧伤停、预测首发写成确认事实。
