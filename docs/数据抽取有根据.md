# 数据抽取有根据

这个 Skill 的核心是先有数据，再有预测。预测准度优先级高于叙事完整度。

## 数据依据表

每次预测前，先输出：

| 数据字段 | 数值/结论 | 来源名称 | 来源链接/标识 | 来源时间 | 新鲜度 | 可信度 | 影响到的模型参数 |
|---|---|---|---|---|---|---|---|

可信度规则：

- 高：官方赛程、官方技术统计、权威数据站、多源一致、接近开赛的确认阵容。
- 中：单一数据站、可靠媒体报道、球队新闻、模型推断。
- 低：社媒传闻、未经确认的预计首发、样本很小的数据。
- 缺失：没有可靠数据，不能作为确定依据。

新鲜度规则：

- 赛程/场地：官方确认后可长期有效，变更风险另列。
- 伤停/预计首发：48 小时内优先，超过 7 天一般视为过期。
- xG/近期状态：应覆盖最新比赛，超过 14 天需说明。
- 赔率：越接近开赛越有价值，必须标注抓取时间。

## 必查数据

- 比赛时间、地点、阶段、主客/中立场。
- 双方近 5 到 10 场战绩。
- 进球、失球、xG、xGA；如果没有 xG，必须找替代指标。
- 射门、射正、被射门、被射正、重大机会、禁区射门、定位球机会。
- Elo / FIFA 排名 / 联赛强度。
- 预计首发、阵型、伤停、停赛。
- 可上场人数、缺阵名单、缺阵主力、存疑主力、位置分布。
- 关键球员近期状态、创造机会、防守贡献、门将表现。
- 战术风格：控球、压迫、反击、定位球、rest-defense。
- 休息天数、旅行、天气、赛程密度。
- 裁判红黄牌尺度、球队纪律、球场质量、海拔、主场氛围、比赛动机。
- 小组积分、淘汰赛背景、轮换动机。
- 1X2 赔率和去水后的市场隐含概率。

## 推荐公开来源

按可用性选择，不强制所有比赛都有：

- 官方赛事/球队网站：赛程、场地、名单、停赛。
- FBref：球队/球员技术统计、xG、射门、传球、压迫相关表格。
- Understat：xG、射门位置、球队和球员进攻质量。
- FotMob / Sofascore / WhoScored：阵容、评分、伤停、近期状态。
- ClubElo / FIFA：球队强度先验。
- Transfermarkt：伤停、球员信息、市场价值参考。
- Football-Data.co.uk：历史结果、赔率、部分技术统计 CSV。
- 新闻源：Reuters、AP、BBC、The Athletic、球队跟队记者等。

## 数据缺失处理

如果数据缺失：

- 在数据依据表中写“缺失”。
- 在模型假设里写清楚替代方案，例如使用 Elo 先验或赛季均值。
- 在球队参数建模中标注“估计值”。
- 在不确定性因素中说明它会影响哪类判断。
- 不要把缺失数据写成确定事实。

## xG 缺失时的替代抽取

如果拿不到可靠逐场 xG/xGA，必须继续抽取这些 proxy 字段，而不是直接放弃：

| 替代字段 | 用途 | 来源示例 |
|---|---|---|
| shotsFor / shotsAgainst | 机会数量底座 | FotMob、Sofascore、WhoScored、官方技术统计 |
| shotsOnTargetFor / Against | 射门质量粗筛 | FotMob、Sofascore、官方技术统计 |
| bigChancesFor / Against | 高质量机会 | FotMob、Sofascore |
| boxShotsFor / Against | 禁区内终结质量 | FBref、WhoScored、官方技术统计 |
| setPieceShots | 定位球威胁 | FBref、Sofascore、官方技术统计 |
| recentGoalsFor / Against | 最低层回归输入 | 官方赛果、Football-Data.co.uk |

报告中要把这些字段写成 `proxy_xG` 或 `goals_regressed_xG`，不能伪装成真实 xG。

## 阵容可用性抽取

阵容信息要拆到可以建模：

| 字段 | 说明 |
|---|---|
| availablePlayers | 预计可上场/在名单内人数 |
| baselineAvailablePlayers | 正常名单基准，默认 23 |
| unavailablePlayers | 明确缺阵名单 |
| doubtfulPlayers | 存疑名单 |
| unavailableStarters | 缺阵预计主力人数 |
| doubtfulStarters | 存疑预计主力人数 |
| unavailableAttackers / Midfielders / Defenders | 按位置统计 |
| lineupContinuity | 预计首发与常规主力结构的连续性 |
| regularStarterShare | 预计首发里经常首发/主力的比例 |
| clubMinutesShareLastYear | 过去一年俱乐部出场分钟稳定性 |
| clubPerformanceAttackImpact / DefenseImpact | 俱乐部赛事表现对攻防的有符号影响 |
| daysSinceLastMatch / matchesLast14Days / matchesLast30Days | 连续比赛强度和恢复时间 |

没有确认首发时，写“预计”或“情景假设”。不要把媒体预测首发写成官方确认。

## 球员数据来源与置信度

每个球员/阵容类字段必须标注来源类型：

| sourceType | 含义 |
|---|---|
| api | 来自 API 或结构化数据源 |
| manual | 人工核验的公开来源 |
| estimated | 模型/人工估计 |
| missing | 缺失 |

必须覆盖：

- availability
- lineup
- injuries
- clubMinutes
- clubPerformance
- keyPlayerImpact
- goalkeeper
- tactical
- setPieces
- penalties

如果 `estimated/missing/unknown` 较多，模型置信度必须降级，并在输出中说明哪些球员数据不是事实。

## 每场特殊因素抽取

| 字段 | 说明 | 来源示例 |
|---|---|---|
| refereeCardsPerMatch | 裁判场均黄牌/红牌、点球倾向 | WorldReferee、赛事官方、历史比赛统计 |
| homeRedCardRisk / awayRedCardRisk | 球队近期红黄牌、战术犯规、情绪风险 | FBref、Sofascore、WhoScored、官方纪律统计 |
| pitchQuality | 草皮/场地质量、是否湿滑或坑洼 | 官方场地报告、赛前新闻、天气转播信息 |
| weatherSeverity | 雨、风、热、湿、冷 | 天气服务、赛事官方 |
| altitudeMeters | 球场海拔 | 场馆资料 |
| homeCrowdAdvantage | 主场压力、开幕战、德比或政治/历史背景 | 官方售票、媒体预览 |
| homeCrowdIntensity | 球迷氛围强度 0-1 | 上座率、球场容量、开幕战/德比、媒体预览 |
| awayTravelFatigue | 客队旅行疲劳 0-1 | 旅行距离、时区、海拔适应、赛程间隔 |
| matchMotivation | 友谊赛、轮换、必须赢、淘汰赛、开幕战 | 积分榜、赛程背景、教练发布会 |

特殊因素必须标注 confirmed / assumed / missing。没有来源时不要硬写“球场差”或“裁判偏严”。

## 临场与定位球抽取

| 字段 | 说明 | 来源示例 |
|---|---|---|
| inGameCoachingImpact | 教练临场调整能力、半场修正、换人倾向 | 历史比赛、媒体战术分析 |
| benchImpact | 替补席质量和角色适配 | 预计替补、俱乐部表现、历史换人贡献 |
| pressingAdaptability | 是否能改变压迫高度和触发点 | 战术报告、比赛录像描述 |
| buildupPressureWeakness | 后场出球抗压弱点 | 失误、被高压抢断、门将出球数据 |
| setPieceAttackImpact | 角球/任意球套路、制空点、二点球 | 定位球进球、角球 xG、球员身高/头球 |
| setPieceDefenseWeakness | 定位球防守弱点 | 定位球失球、盯人失误、门将控制 |
| penaltyTakerReliability | 点球手命中率和压力表现 | Transfermarkt、FBref、公开点球记录 |
| penaltyFrequency / varVolatility | 点球和 VAR 环境 | 裁判、赛事判罚尺度、球队禁区防守方式 |

## 数据冲突处理

如果不同来源冲突：

- 官方来源优先于媒体。
- 多源一致优先于单源。
- 最新确认消息优先于旧消息。
- 预计首发只作为情景假设，不当作确认阵容。
- 冲突会影响首发、伤停、门将、阵型时，必须做情景分支或降低置信度。
